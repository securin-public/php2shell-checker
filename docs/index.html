Am I vulnerable to PHP2Shell?

PHP2Shell lets an unauthenticated attacker corrupt PHP worker memory, read sensitive memory, or run code on affected servers. Enter a domain to check the PHP version it reports.

What is PHP2Shell?

PHP2Shell is the name for two critical vulnerabilities in the PHP language runtime itself, CVE-2026-109618 and CVE-2026-109619. They are memory-safety flaws (use-after-free, CWE-416) in PHP as it processes web requests. They are not bugs in any single application, so any site running an affected PHP version can be exposed, whatever framework or CMS it uses.

SeverityCritical · CVSS 9.2
WeaknessUse-after-free (CWE-416)
Attack vectorNetwork, no authentication
AffectedPHP 5.4 – 8.5 before the fixed releases

Why it matters

An attacker needs no account and no user interaction. Sending crafted requests to a vulnerable server can lead to:

01

Remote code execution

Commands run as the web server's PHP worker account. That gives the attacker a foothold to steal data, plant web shells or move further into the network.

02

Memory disclosure

The attacker can read sensitive worker memory, which can include session data, credentials, API keys and other users' requests.

03

Memory corruption

Corrupting process memory can crash workers and disrupt the service, even when code execution isn't achieved.

End-of-life PHP is permanently exposed. PHP 8.1 and older will not get an upstream fix. Those servers stay vulnerable until they move to a supported branch or to a vendor package with the fix backported.

How to check and fix

  1. 1

    Check

    Enter a domain above. The checker sends one passive request to the site's home page and reads the PHP version it reports in the X-Powered-By header. It then compares that version with the fixed releases.

    Nothing is exploited, nothing is probed beyond that one request, and no targets or results are stored. Page visits are counted anonymously, without cookies.

  2. 2

    Confirm

    A remote version check has limits, so confirm the result on the server itself:

    • Distro packages may already be patched. Debian, Ubuntu, RHEL and similar vendors backport fixes without changing the version number. Check your vendor's advisory.
    • A hidden version is not proof of safety. Many servers turn off expose_php.
    • Only the home page is checked. PHP behind another path or host won't be seen.

    On the server

    php -v

    From a terminal

    curl -sI https://your-site.com/ | grep -i x-powered-by
  3. 3

    Fix

    Upgrade to the fixed release for your branch, or later:

    BranchVulnerableUpgrade to
    8.58.5.0 – 8.5.118.5.12+
    8.48.4.0 – 8.4.268.4.27+
    8.38.3.0 – 8.3.358.3.36+
    8.28.2.0 – 8.2.348.2.35+
    8.1, 8.0, 7.x, 5.4–5.6All releasesNo upstream fix. Move to a supported branch or a vendor package with both fixes backported.

    Development, alpha, beta and RC builds of a fixed version predate the fix and count as vulnerable.
